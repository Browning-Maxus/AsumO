# AsumO Smart Home

## 概要
未来(あす)×Gizmo = AsumO
Flutter×AWS×ESP32の個人開発のスマートホームIoTシステム
常時電源のESP32-PoE IoT Gatewayを経由し、低消費電力のBLEデバイスを遠隔操作する仕組みを開発しています。
スマホアプリからの予約操作に対応し、即時操作や複数デバイスを連携させるワークフロー機能の実装を目指しています。

開発状況：開発途中
AWS IoT CoreからIoT Gatewayを経由したBLEデバイスの操作、及びEventBridge SchedulerからLambda経由での命令送信を実装済みです。

## 設計方針
・Gateway方式：常時電源のIoT Gatewayを作成。デバイスがWi-FiではなくBLEを利用してIoT Coreと間接的にやり取り出来る。
・独自プロトコル：BLEのMTU20Byte 16Byte UUID + 4Byteのパラメータ値でデバイスを制御します。

### ファームウェア見直し
MACアドレスを固有IDとして割り振っている。悪くはないが変更や偽装が可能だし重複も無くはない為、変更したい。
現状アドバタイズだけで電池が数日しかもたない。目標は1日2回動作で1ヵ月。
BLEが思ったより壁などの干渉に弱いので、配置変更だけで何とかなるのか、出力を上げる、プロトコル変更など検証していきたい。

**変更内容**
- device_idの付与
- Automation LightSleep + 1秒間隔30ms程度のアドバタイズループに変更してみて消費電力計測をする。最悪即時動作は諦める。

### APIの拡張
現在はアプリ終了時に全デバイスの取得・保存を行っている。
また、予約動作にしか対応していない。

**変更内容**
- GET /devices/を追加
- PATCH /devices/を追加
- Lambdaの変更・追加

### データベース見直し
現在はDynamoDBの単一テーブルにデバイス情報をすべて保管している
権限が過剰に割り振られてしまうし、責任の分離が出来ていない
またデータの更新頻度やライフサイクルが異なる。

**変更内容**
- テーブルをデバイス情報と予約情報に分離し、最小権限の原理に基づいて、権限分離と権限の適切な付与を行う。
- それに伴いLambdaの変更・追加
